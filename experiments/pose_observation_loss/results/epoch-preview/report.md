# 停止予測に3回の補正位置を使う走行比較

3回の補正を平均する推定器を停止予測へ組み込みましたが、10秒保持の改善は確認できませんでした。新しいseed271〜273では保持が72→70件、既知seed268〜270では69→69件でした。全648ケースで接触・地図外逸脱は0です。追加オプションは既定で無効のままにしています。

## 固定した比較

[前回](../epoch-selection-holdout/report.md)は同じ観測を再生し、位置誤差と仮の操舵弧を比較しました。今回は推定位置を実際の停止予測へ渡すので、停止・解除、その後の走行と観測も変わります。操舵弧の選択器は実行していません。

seed・条件・評価方法を[protocol.md](protocol.md)に保存し、実装を`bfbbb75`で固定してから生成を始めました。3回の補正を使うPython推定器は前回のままで、ソースSHA-256は`1d730cb485768c564ae8a79600a3121cef5609eda95bd3435b18c0ef3e89b3b9`です。結果を見て閾値や制御を調整していません。後述する速度ログの精度だけを改善し、検証済みの走行は`20a32b7`の変更なしの作業ツリーで生成しました。

既存のfine-padding経路を使い、各seedで3地図×3計画法×3欠測条件を実行しました。独立ノイズと相関時間1秒を分け、各群は81対、全体で324対・648ケースです。

`aligned`が比較元で、`epoch`は停止予測のx,yだけを置き換えます。向きは従来の移動補償フィルタのままです。受信から0.5秒以内、速度の絶対値0.02以下の最大25観測を補正ごとに保持し、直近15秒の3回を等重みで平均します。古い2回には各10観測以上、現在の回には1観測以上が必要です。速度・適用済み操舵で現在へ運び、動き始めたときと精密観測への切り替え時には履歴を消します。

利用できない間は従来位置をそのまま使います。観測年齢1.5秒、停止・解除の距離余裕、0.5秒の単独解除、1秒の欠測復帰、実測の復帰直線、速度制限の入力、目標・10秒保持の判定は従来の定義を保っています。

## 推定器の利用と位置誤差

| 群 | 利用したケース / 81 | 利用ステップ | 従来位置の誤差RMS | 融合位置の誤差RMS |
|---|---:|---:|---:|---:|
| 既知・独立 | 53 | 68,238 | 0.14627 | 0.08974 |
| 既知・相関1秒 | 48 | 54,056 | 0.18471 | 0.10524 |
| 新規・独立 | 54 | 64,507 | 0.15014 | 0.08103 |
| 新規・相関1秒 | 41 | 43,719 | 0.19374 | 0.10173 |

全324候補ケースのうち196ケースで利用でき、利用可能230,520ステップ、従来値へ戻した2,212,876ステップでした。利用可能な同一ステップでの全体RMSは0.16661→0.09371でした。

誤差の2列は、epoch走行中に融合を利用できた同じステップで、従来フィルタ位置と融合位置を同じ判断前の真位置と比較したRMSです。別のaligned走行の位置誤差との比較ではありません。行の時刻に対する物理姿勢は更新前の時点で、例えば180秒の判断には179.98秒の姿勢を使います。同じ走行の連続観測が多く含まれるため、ステップ数を独立な標本数とは解釈しません。

位置誤差が小さくなることだけでは、この停止・復帰制御で保持が増えるとは確認できませんでした。融合を利用できなかったステップでは元の位置を使い、全候補ステップで元の向きと履歴の利用条件を照合しています。個々の利用時間・回数・誤差・停止解除への利用は[cases.csv](cases.csv)にあります。

## ログ精度と検証

最初の648ケースは、保存速度の小数9桁への丸めで、推定器の履歴再生に失敗しました。例えば既知独立・blackout・268・dense/A*の10.5秒では、測定速度`2.00000000000013778e-2`が旧CSVでは`0.020000000`でした。実行中の推定器は履歴を消しますが、丸めた値では速度0.02以下と判定してしまいます。

測定速度を往復変換できる精度の`measured_speed`列へ保存し、同じ条件を再生成しました。初回の生データも残し、全648ケースで元の80列と結果CSVが完全一致することを検査しています。推定規則・制御・乱数列は変更していません。初回の検証失敗を成功に数えず、以下の検証は精度を改善した再生成分で実施しました。

全4,881,982移動区間を検査し、候補2,443,396ステップで融合の再構成が通りました。既知162ケースの1,226,697行では、前回の75列すべてと結果CSVが一致しました。初回648ケースの4,882,630行では、追加した速度列を除く80列すべてと結果CSVが一致しました。オプションを省略した追加9ケースも、明示的にfalseを渡した走行と81列を含む軌跡・結果CSV全体がバイト単位で一致しました。

全候補ステップで変更していないPython推定器を再生し、利用可否・保持する補正数・位置・元の向きを照合しました。既存フィルタは別のオドメトリ座標系で再構成し、各成分の差1e-8未満を確認しています。利用開始前の対の既存フィールドも一致しました。

停止予測の厳密照合は5,711地点です。全ガード開始・解除と欠測復帰を含み、終端直線、解除条件と速度プローブを独立に計算しています。全移動区間で自転車モデルの位置・速度・向きの更新を照合し、障害物点と移動線分の半径0.5での接触を別計算しました。接触計算の候補点は、線分を半径分広げた矩形の全点を空間格子から取り、接触し得る点を落としません。地図境界と保持結果も検査しました。

追加17件を含むRust 18件・Python 113件、Clippyの警告なし、整形・構文・差分チェックが通過しました。厳密な速度境界、欠けた補正、履歴の寿命、古い回の必要観測数、移動補償、向きと従来値の維持、共通時間での待機、移動区間の接触検索を検査しました。

## 保存物と再実行

[READMEの手順](../../README.md#run-the-stationary-epoch-position-estimator-in-the-stopping-preview)で新たな4群の走行を生成できます。runnerは単独で検証を完了し、以前の生データを必要としません。集計器は、過去分の原本のハッシュも照合するため、次の保存済み生データを使います。

```bash
python3 experiments/pose_observation_loss/analyze_epoch_preview.py \
  --known-white /workspace/scratch/epoch-preview/verified/known-white \
  --known-correlated /workspace/scratch/epoch-preview/verified/known-correlated \
  --new-white /workspace/scratch/epoch-preview/verified/new-white \
  --new-correlated /workspace/scratch/epoch-preview/verified/new-correlated \
  --reference-white /workspace/scratch/epoch-selection-holdout/white \
  --reference-correlated /workspace/scratch/epoch-selection-holdout/correlated \
  --initial-batch /workspace/scratch/epoch-preview \
  --output /tmp/epoch-preview-summary
```

出力先は新しいディレクトリにします。4つのCSVと実行情報を別ディレクトリへ再集計し、バイト単位の一致を確認しました。生軌跡はGitの外へ保持し、[cases.csv](cases.csv)、[pairs.csv](pairs.csv)、[summary.csv](summary.csv)、[verification.csv](verification.csv)、[sources.json](sources.json)へ結果・実行情報・ソースと生データのハッシュを保存しました。オプション省略の検査は[default-disabled.json](default-disabled.json)に保存しています。

今回の結果から既定の推定器や制御を変更する根拠は得られませんでした。実験コードと結果を再実行可能な形で残し、追加機能は明示的に有効にした場合だけ動作します。
