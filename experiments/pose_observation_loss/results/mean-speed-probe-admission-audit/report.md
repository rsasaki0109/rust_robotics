# 平均位置プローブ試験の復帰条件を診断

平均位置方式で正の予定速度がある11,998判断のうち、9,276判断は別の復帰条件を満たしませんでした。内訳は復帰線の余裕不足3,028、復帰線と解除プレビューの両方の余裕不足6,095、解除プレビューだけの余裕不足153です。速度プローブを通過することだけでは、既存の共同解除条件を満たせない経過を確認しました。

実際の解除は元方式40回、平均方式41回でした。増えたのは独立ノイズ・random・maze/A*の1ケースで、146.16秒に解除しましたが180秒で時間切れでした。保持成功は既報どおり両方式24/54です。これは既存の同じ1-seed履歴の診断で、新しい走行試験や成功確率の推定ではありません。

## 対象と修正記録

元のmainは`394b7631ca3c4c7db348b6c45bb80428989a95ef`です。[protocol.md](protocol.md)と[freeze-pins.json](freeze-pins.json)を`4a77ea6`で先に固定し、旧試験の全16成果物、元のシミュレーター・型・制御、地図・経路、再利用する監査関数など46入力を束縛しました。既知の終端結果や28ペアのログ差・4ペアの終端距離差を踏まえた後ろ向き診断です。全108ケース・54ペア、元の788,988判断を維持しました。

最初の実装`cd2deaf`は、解除余裕量を速度探索余裕量+0.05と仮定していました。最初の一時停止判断で元ログと一致せず停止し、集計表や完了manifestは作りませんでした。curved設定はrecovery_guard_buffer=falseなので、復帰・速度探索側の追加0.1はguard側には入りません。この誤りを[protocol-amendment-1.md](protocol-amendment-1.md)に記録し、元プロトコルと失敗した検証の指紋を[amendment-pins.json](amendment-pins.json)に残しました。

修正した実装`0c951ccb9c693c730110092edb69878be6c35cf9`をコミットしてから、同じ生データを新しい出力先で2回診断しました。修正後は、元の精密観測時の位置sigma=0.03と通常時の設定sigma、復帰余裕量、guard基礎余裕量、解除余裕量の式をそれぞれそのまま抽出しています。固定コマンドの引数、未丸めの観測年齢、記録した精密観測の開始から再計算し、復帰余裕量はfull-precisionログと厳密一致、sigmaと解除余裕量は元の9桁出力と一致させました。

## 同時に失敗した条件

元の7条件は鮮度、停止速度、サンプル数、復帰線余裕、復帰線の両端が地図内、正の予定速度、解除プレビュー余裕です。全条件を同時に満たす必要があります。[gate-patterns.csv](gate-patterns.csv)は各ケースの全一時停止判断と適格判断について、同時失敗マスクをすべて残します。次の表は適格かつ正の予定速度がある判断だけの、重ならない3マスクです。

| 失敗マスク | 元位置方式 | 平均位置方式 |
| --- | ---: | ---: |
| 復帰線余裕のみ | 3,093 | 3,028 |

ここでの復帰線は既存の平均位置・平均yawから伸びる0.6の線分です。候補の速度探索は平均x/yと元の測定yaw・予定操舵による曲線なので、同じ位置を使っても別の幾何条件です。上の集合では最初の3条件を満たし、地図内判定も通っていますが、余裕条件が残りました。

## 1秒の連続成立と解除

267,711回すべての一時停止判断について、共同解除タイマーを独立に再構成できました。解除距離の丸めによる未確定ゲートと、未検証のタイマーステップはともに0でした。

全成立の連続区間を482本保存しています。50ステップ×0.02秒で解除し、それより前に条件が失敗するとゼロへ戻る元の処理を確認しました。区間は重複する同じケースの履歴に由来するため、482個の独立試行ではありません。

[admission-runs.csv](admission-runs.csv)には全区間の開始・終了、長さ、終了理由と直後の全失敗マスクがあります。途中の短い成立区間は元方式合計1,773ステップ、平均方式672ステップでした。区間数の減少だけでは保持成功の増加を意味しません。

前試験で終端距離が変わった4ペアの解除履歴もすべて示します。相関時間はいずれも0秒で、両方式とも180秒で時間切れです。

## 検証と再実行

元のPoint2Dと線分距離関数、復帰線の端点・障害物走査・境界式を使い、全一時停止判断を標準ライブラリのRustで再評価しました。[admission-geometry.rs](admission-geometry.rs)は完全な生成ソースです。ネイティブの復帰距離を9桁に書式化した値が元ログと一致し、境界の包含判定は元コードのままです。

解除プレビューの距離は元ログの9桁丸め区間±0.0000000005と、再構成した未丸めの解除余裕量を比較しました。端点だけの注記には、距離と余裕量の両方の丸め区間を使います。閾値の重なりを残す処理は合成テストで検査しています。今回の全共同解除判断では、重なりによる未確定はありませんでした。

修正後の全1,339テストが成功し、失敗・エラー・skipは0件でした。追加17テストは元の線分幾何、境界の等号、精密sigmaと別々の余裕量、49/50ステップ、途中リセット、未確定の伝播、改変検知を含みます。2回の全診断では、4表・出所・ネイティブソース・入力・出力・ビルド記録・バイナリの10ファイルがバイト単位で一致しました。[replay-verification.json](replay-verification.json)に指紋と108件のネイティブカウンター照合を記録しています。

Python 3.12、Rustコンパイラ、クリーンなコミット済みチェックアウトと元の生データ一式を使います。出力は存在しないリポジトリ外のパスにします。

```bash
python3 -B experiments/pose_observation_loss/analyze_mean_probe_admission.py \
  --raw /path/to/mean-speed-probe-raw --output /tmp/mean-probe-admission-1
python3 -B experiments/pose_observation_loss/analyze_mean_probe_admission.py \
  --raw /path/to/mean-speed-probe-raw --output /tmp/mean-probe-admission-2
```

この環境の元生データは`/workspace/scratch/mean-speed-probe-live-pilot/raw`です。失敗した最初の検証と、修正後の完全な2回の結果は`/workspace/scratch/mean-speed-probe-admission-audit/aggregate-{1,2,3}`に残しています。大きな入力TSV・ネイティブ出力・バイナリは各native/以下にあり、コンパイラと指紋は[native-sources.json](native-sources.json)、固定入力・出力と実装の指紋は[sources.json](sources.json)にあります。診断中の新しいシミュレーター走行は0件です。

この履歴では、正の予定速度のほかに復帰線と解除の余裕判定が残り、連続成立や解除が得られても保持成功に十分ではありませんでした。この必要条件の診断から、判定の削除・余裕量の縮小・一般的な安全性や有効性は導きません。
