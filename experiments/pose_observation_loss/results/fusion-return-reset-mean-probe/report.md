# 平均位置で19件の曲線プローブを再評価

位置のx,yだけを記録済みの定常平均へ置き換えると、19判断のうち18判断で探索上限の2mまで通過しました。残るC0310@8795は第5区間で失敗し、返却距離は0.20mでした。元の位置では19判断とも記録どおり距離ゼロとなり、両方式の38計算が変更していないRust関数と一致しました。

これは、既知のリセット地点について向き・操舵・余裕量を固定した同一時点の幾何比較です。実際の解除、タイマー、走行、接触、10秒保持は再計算していません。平均位置を使う制御器の改善を示す結果としては扱いません。

## 先に固定した条件

[protocol.md](protocol.md)と[freeze-pins.json](freeze-pins.json)を`bc56aa1`でコミットしてから、それまで抽出していなかった17判断の予定操舵と新しい平均位置プローブの結果を読みました。元のmainは`4fcb8a8365dadf6280adb1a41909d9291a974496`です。判断の選択と点の比較結果は既知であり、新しい盲検試験ではありません。

元の19リセットを元の順序で保持しました。4つの履歴・2つのfamilyに由来し、重なった区間末尾の多重度は合計185です。この多重度を独立した試行数とはしていません。元の開始点失敗17件、最初の区間の失敗2件、同時に失敗した全ゲートも残しています。

元ログはfresh-whiteのcurved-random-278とepoch-random-278の2本です。それぞれ71,910行を読み、全ファイルのSHA-256を以前のfirst-chord監査と照合しました。各判断の行と直前の行を選び、既存のsurplus表にある入力文字列も比較しました。[selected-inputs.csv](selected-inputs.csv)は19行・18列で、行番号、真値から元の測定を再構成するための入力、予定操舵、元の速度探索値を保持します。再評価時には、この小さな抽出だけで再実行できます。

## 位置以外を同じにした再評価

元の測定位置と向きは、直前行の真値に現在行のノイズとバイアスを元の2回の加算順序で足して再構成しました。平均方式ではx,yだけを以前のdecision_mean_x_center / decision_mean_y_centerに置き換えます。向きは元の測定のままで、平均の向きには置き換えていません。予定操舵の再選択、余裕量の縮小、障害物の選別も行っていません。

全地図レコードを渡し、元の関数と同じ開始点から距離2+margin以内の近傍選択を、各方式の開始点に適用しました。開始点の壁・障害物との接触を先に検査し、元の固定操舵に沿って0.05mずつ40区間を検査します。壁と線分への距離は余裕量以下で失敗です。最初の失敗区間がkなら返却値は(k-1)*0.05、全区間が通れば2.0です。元のsin/cos差分と曲率の分岐を維持しています。

これらは丸めたログから得た中心値です。元の未丸め状態、平均位置の不確かさ全体、連続した曲線全体の誤差上限を検証したという主張はしていません。Rustとの一致は、同じ中心値を渡したときの元の探索関数の結果の照合です。

## Rustによる照合と再現性

独立verifierはcollectorをimportしません。固定したリポジトリからspeed_free_distance、point_segment_distance、Point2Dの距離・コンストラクタ、VehicleStateとホイールベースを抽出し、標準ライブラリだけでRustの照合プログラムをビルドします。探索関数の本体はそのままです。全38入力で、距離、開始点判定、失敗区間、同時に失敗する壁と障害物の全IDがPythonと一致しました。速度上限と仮の予定速度は別に60桁Decimalで計算し、絶対誤差1e-12以内で照合しています。この数値比較の許容差は、幾何判定には使っていません。

抽出・集計・Rust検証をそれぞれ新しい出力先で2回実行しました。抽出CSVと出所、2つの結果CSVと出所、Rust照合プログラム、38入力、ネイティブ出力、検証JSONの9ファイルがバイト単位で一致しました。元ログの行番号を直接たどる別の読み出しでも、19判断の入力文字列が一致しました。元の生ログ2本の読み直しを含みますが、新しい観測や走行データの生成はありません。38回のRust関数呼び出しは、新しい走行38件を意味しません。

## 再実行

Python 3.12の標準ライブラリと有効化したRustコンパイラを使用し、リポジトリのルートで実行します。出力・work・検証JSONはいずれも存在しないパスを指定してください。

```bash
python3 -B experiments/pose_observation_loss/analyze_reset_mean_probe.py \
  --output /tmp/reset-mean-probe
python3 -B experiments/pose_observation_loss/verify_reset_mean_probe.py \
  --results /tmp/reset-mean-probe --work /tmp/reset-mean-probe-native \
  --output /tmp/reset-mean-probe-verification.json
```

元ログがある環境では、入力抽出も作り直せます。以前のfirst-chord監査の出所に記録した元ディレクトリを使います。移設した場合は--raw-rootで元のfresh-whiteルートを指定します。内容のSHA-256が一致する必要があります。

```bash
python3 -B experiments/pose_observation_loss/analyze_reset_mean_probe.py \
  --extract-raw --output /tmp/reset-mean-probe-inputs
```

別の出力先で繰り返し、selected-inputs.csvとselected-input-sources.jsonを比較できます。新しく抽出した入力を使う場合は、collectorとverifierの両方に--inputs /tmp/reset-mean-probe-inputsを渡します。
